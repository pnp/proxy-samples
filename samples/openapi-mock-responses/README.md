# Mock an API from its OpenAPI spec

Mock an entire API from its OpenAPI spec, with realistic responses generated by a local language model when the spec has no examples

![Dev Proxy returning mock responses generated from an OpenAPI spec](assets/screenshot.png)

## Summary

This sample shows how to mock an API using only its OpenAPI spec with Dev Proxy's `OpenApiMockResponsePlugin`. You don't need to write mock files. Dev Proxy reads the spec, matches incoming requests to its operations, and returns responses based on what the spec defines.

The sample includes the OpenAPI spec for a fictional Contoso Store API (`https://api.contoso.com/v1`) with products, customers, and orders. Some operations include response examples in the spec. Others only define a schema. For those, Dev Proxy uses a local language model to generate realistic data. If no language model is available, it falls back to values based on the schema types.

## Prerequisites

- [Dev Proxy](https://aka.ms/devproxy) v4.1.0 or later
- Optional: a local language model, such as [Ollama](https://ollama.com), to generate realistic responses. See [Use a local language model](https://learn.microsoft.com/microsoft-cloud/dev/dev-proxy/how-to/use-language-model) for setup instructions.

## Minimal path to awesome

- Get the sample:
  - Download just this sample:

      ```bash
      npx gitload-cli https://github.com/pnp/proxy-samples/tree/main/samples/openapi-mock-responses
      ```

    or

  - [Download as a .ZIP file](https://pnp.github.io/download-partial/?url=https://github.com/pnp/proxy-samples/tree/main/samples/openapi-mock-responses) and unzip it, or
  - Clone this repository
- Open a terminal in the sample folder, for example, if you cloned the repository: `cd samples/openapi-mock-responses`
- Optionally, start your local language model, for example Ollama:

  ```bash
  ollama serve
  ```

- Start Dev Proxy with the configuration file from the sample:

  ```bash
  devproxy
  ```

- Send requests to the Contoso Store API, for example using curl:

  ```bash
  # List products (response taken from the example in the spec)
  curl -ikx http://127.0.0.1:8000 https://api.contoso.com/v1/products

  # Get a product (response generated from the Product schema)
  curl -ikx http://127.0.0.1:8000 https://api.contoso.com/v1/products/42

  # Create a product (returns 201, the lowest 2xx status code defined in the spec)
  curl -ikx http://127.0.0.1:8000 -X POST https://api.contoso.com/v1/products \
    -H 'Content-Type: application/json' \
    -d '{"name":"Contoso Rain Jacket","price":129.99}'

  # Delete a product (returns 204 without a body)
  curl -ikx http://127.0.0.1:8000 -X DELETE https://api.contoso.com/v1/products/42

  # List customers (response generated from the Customer schema)
  curl -ikx http://127.0.0.1:8000 https://api.contoso.com/v1/customers

  # List orders for a customer
  curl -ikx http://127.0.0.1:8000 https://api.contoso.com/v1/customers/abc123/orders
  ```

## Features

Using this sample you can use Dev Proxy to:

- Mock an API using its OpenAPI spec without writing any mock files
- Return responses based on examples defined in the spec
- Generate realistic responses with a local language model for operations without examples
- Fall back to schema-based values when no language model is available

### How it works

The sample's configuration (`.devproxy/devproxyrc.json`) enables the `OpenApiMockResponsePlugin` and points it to the OpenAPI spec using the `specFile` property:

```json
"openApiMock": {
  "$schema": "https://raw.githubusercontent.com/dotnet/dev-proxy/main/schemas/v4.1.0/openapimockresponseplugin.schema.json",
  "specFile": "contoso-api.yaml"
}
```

`specFile` can be a path to a local JSON or YAML file, relative to the configuration file, or an http(s) URL. Dev Proxy watches the local spec file for changes and reloads it automatically.

For each request to a URL in `urlsToWatch`, the plugin:

1. Matches the request against the paths and operations in the spec. Path parameters, like `{productId}`, match any value. Requests that don't match any operation are passed through to the actual API.
1. Picks the response status code: the lowest 2xx status code, then `default`, and otherwise `200`.
1. Builds the response body, using the first available source:
    1. The example defined in the spec for the response.
    1. Data generated by the language model, based on the response schema and its property names. To enable this, the sample turns on the language model in the configuration (`"languageModel": { "enabled": true }`). By default, Dev Proxy uses Ollama running locally.
    1. Values generated based on the types in the schema.

Generated responses are cached in memory per operation (method and path template), so you get consistent responses for the same operation until you restart Dev Proxy or change the spec.

### Mock your own API

To mock your own API, replace `contoso-api.yaml` with your API's OpenAPI spec, update the `specFile` property, and update `urlsToWatch` to match your API's URL.
